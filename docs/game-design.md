# Ivy — 游戏设计说明（iOS App 评审稿）

Date: 2026-09-16  
Product: 原生 iOS App（SwiftUI），礼物用 TestFlight 发给他  
Repo: 独立仓库（桌面 `ivy/`），与 Pocket 无关  
Pixel kit: `public/pixels/`（画布 160×240，给 App 当素材；本仓库里的 Vite 页只用来预览像素）  
Audience: 作者评审  
Status: 待评审。通过后再写实现计划。

相对上一版网页稿，**玩法支柱、十个彩蛋、抽奖必中**不变。变的是产品形态：从「打开链接」改成「主屏幕上的一盒卡带」，场景、输入、反馈、分发按 iPhone 重做。

---

## 0. 一句话

**Ivy 是一个只装在他手机上的 16-bit 单房间点选收集游戏：拇指近看、系统键盘偶而打字，十件私人物件进栏；收齐后开一次抽奖，必中你准备好的奖。**

不是网站，不是 App Store 上架的公开产品，不是锈湖全长。

---

## 1. 概念定义

### 1.1 三根支柱（动词，未改）

1. **近看** — 点家具进入特写。  
2. **收下** — 点收或打对字，栏里亮起 icon。  
3. **屋子记住** — 每收一颗，藤或摆设变一点。

这个游戏是 **近看、收下、看屋子慢慢被藤盖住**。

不做：跑图、战斗、合成、死亡、每日打卡、推送催他打开、桌面小组件打卡。

### 1.2 问题陈述（环境已换）

**焦点：** 人在杭州、工作忙、**iPhone 竖屏**。地铁或躺着单手玩。礼物应是主屏幕上的图标，不是浏览器书签（忙人会把标签页丢掉）。

**可衡量的成功：**

- 装完第一次能在 **8–15 分钟** 收齐或安心退出（进度写在设备上，杀掉 App 还在）。  
- 十颗里至少四颗不靠你提示能认出（Vuori、gelato、烧鹅粉、两场电影）。  
- 输入时键盘不挡住确认按钮；输错不丢进度。  
- 他觉得这是你做的一盒游戏，不是 H5。

**表达：** 锈湖观察感 + 你们的物件；像素石屋；**触感（Haptics）是 iOS 上核心循环的直接反馈**，网页做不到同样质感。

### 1.3 80/20

80% 时间：房间里点。  
20%：intro、三次输入、抽奖。  
iOS 多出来的工作（安全区、键盘、TestFlight）不要膨胀成第二个玩法。

### 1.4 约束三角

要 **好**（原生手感）和 **范围小**。速度靠：一屏游戏、现成像素、TestFlight 而不是上架审核。

**不选：** 用 WKWebView 包 Vite 预览页冒充 App。能更快，但键盘、触感、生命周期都是网页的，和「做成 iOS app」的目标不一致。本仓库的 Vite 工程只当像素工坊。

## 3. 主题（未改）

**一座石屋被藤慢慢覆盖 —— 你们把彼此写进日常物件里。**

环境叙事照旧：空枕、双窗、未锁箱子、糊掉的日历、藤 = 进度。

版权：歌词不上屏，只在设备里校验一句短答案。

iOS 额外的主题载体：**App 图标和启动画面就是那座石屋**，第一眼锚定（锚定效应）在「卡带」而不是「工具 App」。不要用 SF Symbols 做主界面。

---

## 4. 核心循环（动词未改，反馈改成 iOS）

```
拇指点房间
    → 轻触感 + 废话考察  或  全屏特写
        → 再点收下  或  系统键盘输入
            → 成功触感 + icon 进栏 + 屋子变一点
                → 还想点下一个角落
```

易懂、拇指能点、点一次有反馈。Haptics 是循环里的「跳起来」那一下，不是装饰。

**两种动词：**

| 动词 | iOS 操作 | 成功 | 失败 |
|------|----------|------|------|
| 点 | 房间 → 特写（可下滑关掉）→ 再点物件 | 进栏 | 无失败；废话只说话 |
| 输入 | 点手机/藤/日历 → 底部输入板 + 系统键盘 | 规范化后匹配 | 提示；键盘不收；进度不扣 |

无合成、无拖拽、无限时。

**输入键盘分流（降低错误行动）：**

| 彩蛋 | 键盘 |
|------|------|
| `vuori` | 英文 ASCII |
| `ivy` | 英文（歌词短句） |
| `sep29` | **数字键盘**（只接受 929 / 9.29 / 0929 规范化） |

**心流：** 记忆型，不是技能型。三次打错后加强提示，歌词仍不引用整句。

## 5. 体验结构与节奏

仍是 **小沙盒房间 + 线性收尾**。十个全自由；#6 日历不锁顺序；十槽满抽奖机才亮。

| 时间 | 段落 |
|------|------|
| 0:00 | iOS 启动画面：夜色石屋一帧（不是白底系统 Launch）。 |
| 0:00–0:20 | Intro 藤爬墙，可 Skip。 |
| 0:20–2:00 | 入门点：gelato / 碗 / 海报（光下、屏幕中下部，靠近拇指）。 |
| 2:00–8:00 | 窗、箱、房卡、空枕、Vuori。 |
| 最后 | 藤或日历；抽奖。 |

2 分钟零收集：灯光热点轻微闪（运动捕获）。不要系统 Alert「需要帮助吗」。

切去微信再回来：停在原特写/输入板；键盘状态可丢，内容保留。

## 6. 场景设计（按 iPhone 重排）

逻辑画布仍是 **160×240**，居中放大到可用宽度，上下用 `night` 色信箱。像素最近邻放大，不模糊。

**安全区：** 游戏画布不伸进 Dynamic Island / 刘海。物品栏贴在 **home 指示条上方** 的 `safeAreaInset`，不与指示条抢点（Fitts：热区高度不够会点错）。

**锁定竖屏。** 不支持横屏、分屏、台前调度第一版。

**不要 Tab 栏、不要导航栈一堆页面。** Hick：整 App 对玩家只暴露「这一间屋」。系统导航栏隐藏。

### 6.1 启动画面

静态像素石屋（可用 `intro-house.png`）。无进度条、无「Loading」。

### 6.2 场景 A — Intro

全屏（含安全区铺夜色）。点「伸手」或点屋子播放藤四帧。右上 SKIP，放在安全区 **内**，至少 44×44 pt 点击盒（系统最小触控；像素按钮视觉可以更小，热区要放大）。

首次启动走 intro；之后进房间。没有单独「设置页」；收齐后抽奖信角落可「再看片头」。

### 6.3 场景 B — 房间（唯一玩的画面）

固定机位看后墙。点的是画布上的矩形热点，不是 HTML。

布置（上远下近，**可点大件放中下**，方便拇指）：

```
        [窗-深]     [日历]     [窗-杭]
        [藤 左侧墙]
[外套+手机]  [gelato]  [烧鹅粉]  [海报]
[床+空枕]    [行李箱]  [房卡]    [抽奖机]
──────────── 物品栏 10 槽（safe area 上）────────────
                    Home 指示条
```

入门三件（杯、碗、海报）在中带、靠窗灯。Vuori 手机、日历更靠上、更暗。

废话热点：灯、地毯、梁。抽奖机先灰，十个齐了亮。

**Fitts：** 热点视觉可小，命中盒 ≥ 约 44 pt。相邻热点不要重叠超过 30%，宁可空隙大一点。

**误触：** 从底边滑 Home 不要当成点空枕。物品栏与画布之间留 4–8 pt 死区。

**手势：** 房间内 **不用** 边缘返回（会和系统返回冲突，属于流程错误）。特写才允许下滑关闭。

### 6.4 场景 C — 特写

覆盖房间的全屏层（不是 Safari 式 push）。上：特写像素；下：对话框。

关闭：下滑 或 点「返回」（热区 44 pt）。下滑是 iOS 习惯，降低「找不到返回」。

特写里才出现 8.17、两张电影票、嫌弃 gelato 的话。

### 6.5 场景 D — 输入（键盘是关卡的一部分）

**错误处理：** 键盘挡住确认 = 流程错误。输入板必须用键盘避让，确认按钮始终在键盘上方可见。

形态：底部像素面板 + `TextField`。占位符不要写成答案。确认是面板上的像素按钮，同时支持键盘 Return（数字键盘例外，929 用面板确认）。

打错：提示换句，文字留着改。点空白不强制收键盘，避免误关。

### 6.6 场景 E — 抽奖

十槽满 → 机身亮 + 可点。短像素动画。**必中预置奖**（信 + 可选照片，`frame-photo`）。再点只重读。

奖面：全屏信，照片在像素框里，人脸不像素化。可以捏合看清照片（系统 `Magnify`，可选；第一版双击放大即可）。

## 8. 物品栏与 icon

十槽顺序固定 1→10。未收剪影，已收彩色。点已收：再读考察。

icon 16×16 逻辑像素。栏在安全区上，单槽热区加宽，十个并排在 iPhone SE 上仍可点（必要时两行 5+5，第一版优先一行；SE 太挤再改两行）。

槽满 = 抽奖机亮灯的可供性。

## 9. 反馈与容错

| 事件 | iOS 反馈 |
|------|----------|
| 废话家具 | `.soft` 触感 + 冷考察 |
| 进特写 | `.light` |
| 收下 | `.medium` + icon + 屋子变 |
| 输入对 | `.success` |
| 输入错 | `.warning` + 提示；≥3 次面包屑 |
| 抽奖 | `.success` 一次 |
| 杀进程 | `UserDefaults`（或 SwiftData 单条存档）：已收 id、intro、已抽奖 |

无生命、无 Game Over。不申请通知、不申请追踪、第一版不申请相册（照片打进包内）。

**运动控制错误：** 点偏 → 命中盒大于贴图。  
**遗漏：** 2 分钟闪灯，不是 Banner。  
**错误行动：** 数字题用数字键盘，减少把 929 打成别的。

| 项 | 决定 |

### 本版不做

- WKWebView 套网页。  
- 第二房间、合成、拖拽。  
- 歌词上屏、内置歌曲文件（可外链系统音乐 App，第一版不做）。  
- 真随机奖池、排行榜、iCloud 同步、Watch、小组件、推送。  
- 上架 App Store。
