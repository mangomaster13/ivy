# Ivy 图片生成：真实空间与透视规则

适用：新场景设计、照片参考再创作、现有图片修改、独立物件素材及主景／近景变体。配合 imagegen 的结构化提示与单项修改方法使用；本文件定义画风与空间规则，[UI-RULES](../ui/UI-RULES.md) 定义交互与界面约束。绘本风格允许笔触夸张，不允许空间结构失真。

## 全游戏画风基准：Yard

用户指定 Yard 为今后 Ivy 图片的画风基准。以当前 `art/yard/source/yard-closed.png` 和 `yard-open.png` 的房屋、植被、石路及光影作为**场景画风**锚点；开关门两张只改变门的状态。`art/yard/review/open-yard-app.png` 只用于观察实际显示比例，不把截图中的文字、底栏或黑边画进场景。Yard 的高清信纸、锁板等近景只证明近景需要清晰材质，不能取代主景的画风锚点。Hall 和其他场景可供核对地点与物件，若画法有差异，以 Yard 为准。

- **形与笔触：** 先用简明、可读的整体轮廓和成组色块建立房屋、家具、植物和道具，再用可见的短笔触、阶梯状边缘与少量颗粒纹理刻画材质。轮廓偏深蓝黑或深褐，边缘保留手绘起伏；细节服从主体，不用密集均匀噪点填满画面。
- **光与色：** Yard 的深海军蓝夜空、青绿植被与石材阴影对照窗灯、灯笼和门内的局部暖琥珀光。暖光只照亮邻近表面，暗部仍能辨认结构和可互动物件。其他地点可以有自己的时间、天气和物件色，但保持这种克制的冷暖关系与清楚的明暗层次，不把每个场景强制画成夜晚。
- **材质：** 石、旧木、纸、布和植物以哑光色块及不规则纹理表现体积。玻璃与金属只在合理受光处有小面积高光；雨地可有少量宽而柔和、断续的反射。保留真实材质差别，不做整面镜面水膜、描金发光边或摄影式 HDR 泛光。
- **清晰度：** 保留 Yard 的像素绘本气质，而非统一降采样。场景、近景和独立透明物件都从高分辨率原稿直接导出各倍率；近景可有比远景更细的纸纹与物件细节，但轮廓、色块、笔触、光向仍属于同一世界。不要用整图压暗、去饱和、模糊或最近邻放大来伪造一致性。
- **同一世界：** 侧视角、近景、开关状态、物件精灵与主景共享相机逻辑、比例、材质、光向和轮廓语言。局部改画风时锁定已批准的构图、家具尺度、支撑面、过道、门窗和玩法物件位置；设计稿获认可后再接入游戏。

生成或编辑时，将 `art/yard/source/yard-closed.png` 作为画风参考传入，并在提示中明确：`Match Ivy Yard's hand-painted pixel-storybook visual language: readable dark hand-drawn contours, broad grouped color shapes, restrained stepped brush texture, matte stone/wood/foliage, deep blue-teal shadows and localized warm amber light. Keep material detail crisp at the intended output resolution; do not turn the image into low-resolution pixel art, smooth vector art, photorealism, glossy 3D, bloom or HDR. Preserve the target scene's approved camera, geometry, support surfaces, object identities and states.` 再单独说明目标场景的相机、天气、时间、实物参考和本轮唯一修改；不让 Yard 的房屋构图或夜景照搬到其他地点。

交付前将新图与 Yard 主景并排看：轮廓是否同样清楚、色块和颗粒是否同样克制、暖光是否局部、材质是否哑光；再对照目标场景检查相机、物件和状态。偏差可明确指出的稿件继续修订，不因提示词正确就视为风格通过。

## 生成前先明确空间

1. **区分参考职责。** 标明哪张约束空间／相机，哪张约束实物造型，哪张只提供画风。先查看参考，不能仅凭文字猜测。用户选定的构图是编辑不变量，不用后来的生成图覆盖它。
2. **确定同一台相机。** 写明视点高度、俯视程度、取景范围和透视类型；根据参考推断，不虚构精确焦距。一个画面使用一致的地平线；同方向平行边朝同一消失方向收敛，不同朝向物件可有各自消失点。不能让桌面是俯视、瓶身却是完全平视。
3. **先放建筑与家具。** 明确前景桌子、中景过道、后景柜台的位置关系。保留真实桌深、柜体厚度、座位与桌面高度关系、开门空间和通行路径。不要为了容纳道具把桌子延伸到柜台、消灭过道或改变房间尺度。
4. **用相对尺度核对。** 以门、座椅、桌面和常见杯碗作参照；近大远小来自距离与相机，不能让每件道具各自缩放以填满画面。桌面不够时先减少装饰、调整摆放或设计独立近景；不得擅自拉长家具或把关键道具缩成难以辨认的小点。
5. **列出物件数量与状态。** 区分当前画面必须出现、已拿走、不应出现的物件。Big Top 上菜态必须有半只烧鹅、一碗米饭、一碗粉、一杯柠檬茶、一杯阿华田；菜单获取前后不混用。设计总览若合并状态，必须标注不能直接作为运行时场景。

## 物件怎样真实地落在场景中

涉及物件放入凹槽、盒子或落在承载面上时，同时遵循[物件与容器贴合规范](../ui/object-container-fit.md)：先设计正确的组合态，再拆分素材；明确相机、入槽姿态、间隙、支撑锚点与前沿遮挡，不能拿库存正面图直接充当放置态。

- **支撑与投影分开。** 平放菜单、抹布、盘子的完整占地在承载面内；杯瓶的底部稳落在桌面／层板上，竖直部分可以按透视高于桌面后沿。禁止为了把杯身二维轮廓框入桌面而加深桌子。柜格还须满足顶部和侧面的真实净空。
- **接触必须成立。** 底部与支撑面相接，接触阴影解释重量；不能悬空、穿板、嵌入桌沿。布料跟随承载面，不无支撑地悬伸。玩家未明确要求时不添加垂落桌沿的物件。
- **遮挡关系一致。** 前后层级符合空间深度；一件物体不能同时在另一件物体前后穿插。抽屉、门、盒盖与铰链的开启方向应可实现；开启后不能穿墙或穿过其他物件。
- **圆形与厚度跟随透视。** 碗口、杯口和瓶底的椭圆方向与视点一致；同一物体上下截面要自洽。桌沿、柜门、书册保留合理厚度；竖直线是否收敛由相机决定，不混用透视模型。
- **光照来自场景。** 独立素材与背景共用主光方向、色温及合理阴影；透明玻璃和液面要有一致的折射／反射方向，不能像高亮贴纸。不要让每个道具带不同摄影棚光线。
- **文字贴合实体。** 招牌／标签文字在留边内排版，跟随其表面透视和旋转；不能像屏幕文字悬在物件前。按 UI-RULES 最新文字素材规则，Notes 和 lock pad 的交互文字保留原生，Dictionary 玩家笔迹运行时绘制，其余文字设计为物件素材或共用变换的独立题字素材；精确拼写在素材制作中保证，不能以临时原生文本替代设计。交互与无障碍语义保持独立。

## 每次图片请求的必填提示骨架

按任务填具体内容，不将模板占位词原样提交：

- 用途与风格：内容区设计稿／独立素材；Yard 参照的 Ivy 像素绘本画风。
- 参考职责：空间与相机参考、实物造型参考、画风参考。
- 相机与空间：地平线／视角、前中后景、家具尺度、过道和开门空间。
- 物件清单：名称、数量、状态、支撑面、摆放与遮挡。
- 光照与文字：主光、阴影、精确文字、招牌内框。
- 必须保留：批准构图、桌子前后沿、相机、门窗、未改动物件。
- 本轮只改：一个具体目标；不连带改变家具和其他道具。
- 输出：完整场景或独立透明素材，不烘焙游戏控制按钮。

## 出图后、交付前

逐项查看生成图片本身：与 Yard 的轮廓、色块、笔触和光影一致性 → 相机与收敛关系 → 家具比例及过道 → 物件支撑和遮挡 → 数量及状态 → 文字与独立素材身份。不能因为提示里写了要求就认定图片已经满足，也不能将生成器的完成说明视为验收证据。

发现局部问题，使用最后一张正确的参考做单项修改，并再次声明空间不变量。若修改破坏了已正确的家具比例或丢掉物件，退回正确版本继续，不以错误版本累积修改。仍不合格的稿件标为待修订，不称可直接开发。

保存选中设计、提示、参考职责和待解决项；被用户否决的长桌等版本不得再成为默认素材。设计确认后才拆分素材接入；主景／近景分别记录相机和支撑锚点，禁止只把同一精灵拉伸成另一种透视。

这些是生成图片的审稿步骤，不是运行游戏的截图或测试授权。构建、设备与交互验证仍遵循项目的用户测试政策。
