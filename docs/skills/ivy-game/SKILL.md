# Ivy 项目工作流

这是仓库内的项目专用 skill，由根 AGENTS.md 引用；相对链接以本文件为起点。无需假定已安装为全局 skill。

1. **确定基线。** 读取 [游戏总纲](../../gameplay/IVY-GUIDE.md)，确定目标地点、用户最新要求和保留的玩法。前段场景读[当前 PRD](../../product/PRODUCT.md)与[9 月 21 日整改](../../product/2026-09-21-playthrough-revision.md)；香水铺后读[后四站设计稿](../../gameplay/2026-09-23-later-eggs-tool-design.md)。`perfume` / `dictionary` 是目标收藏名称，旧 `supermarket` / `sunset` 存档必须迁移。区分当前实现、确认设计和待审提案；历史计划和旧稿不能覆盖最新修订。
2. **按任务读取规则并确认现用素材。** 涉及界面、文案、交互或素材，读取 [UI 规则](../../ui/UI-RULES.md)；涉及代码、状态、存档或布局，读取 [开发原则](../../engineering/DEVELOPMENT.md)。选图时先从目标场景代码使用的图片名和 `ios/Ivy/Assets.xcassets` 中的 imageset 确认当前运行图，再沿对应导出脚本反查 `art/` 中的生产源图；新场景或尚未接入的图以用户最新批准的具体设计／参考为准。`art/` 中的旧版本、review 图和草稿仅作历史资料，不能凭文件名、日期或目录顺序当作现用图。仅深入目标场景的专项资料，不加载全部旧计划。
3. **落实实物与状态。** 让入口、近景、工具动作、打开／拿取／消耗、收藏与返回路径彼此一致；明确中间状态和旧存档如何保留。复用现有共享机制。需要先看设计稿的请求先交具体稿；已有批准直接执行，不重复确认。
4. **完成接入。** 在任务范围内同步素材、热点、布局和状态守卫，保护共享工作区的其他改动。按 UI 规则的用户测试政策交付；普通任务不启动测试、校验脚本、验证构建或设备。明确调试／测试任务才做相应轻量验证。
5. **准确交付。** 说明已完成的改变及实际验证范围，不将设计稿、编译或历史通过记录视为手势验收。新的明确偏好更新权威规则，局部例外记录适用对象，不扩张成全游戏禁令。
